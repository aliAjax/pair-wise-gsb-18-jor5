# hxwl-04 牙科根管治疗 · 根管复诊闭环

按牙位 × 根管记录工作长度、主尖锉号、封药次数与下次复诊日，规则引擎驱动"测长 → 封药 → 复诊 → 充填 / 显微会诊 → 冻结修订"全闭环。

## 技术栈

React 19 + Vite + TypeScript + CSS（localStorage 持久化，无后端依赖）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5104；类型检查 `npx tsc --noEmit`，打包 `npm run build`。

## 数据层级

牙位病例（ToothCase）→ 版本链（CaseVersion[]，只追加）→ 根管（Canal[]）→ 测长事件 / 封药事件。

- 每个根管独立维护：工作长度历史、主尖锉号、封药次数与逐次干燥情况。
- 下次复诊日挂在牙位版本上（日期 + 类型：常规复诊 / 显微会诊）。

## 闭环规则

| 规则 | 内容 | 拦截点 |
| --- | --- | --- |
| R1 | 任一根管未测量工作长度，禁止进入充填 | 充填确认（弹窗按根管列出阻断项，按钮禁用并登记冲突） |
| R2 | 工作长度较上次缩短超过 1mm，必须填写重新测长原因 | 测长保存（缺原因即拦截） |
| R3 | 连续封药两次仍未干燥，下次复诊只能安排显微会诊，不能直接充填 | 安排复诊（类型被锁定为显微会诊）+ 充填（双重拦截） |
| R4 | 已充填病例冻结，任何更正只能新建带原因的修订版，旧版完整保留 | 冻结病例全部写操作；"申请修订"生成 v(n+1) 并展示修订链 |
| R5 | 刷新加载时校验牙位 / 根管 / 复诊 / 修订链一致性 | 应用启动审计，问题按内容去重后登记为 R5 冲突 |

## 冲突台账

每次规则触发都会留痕，固定列出：**时间、牙位、根管、字段、原值、新值、触发规则、说明、状态**，支持标记处理；R5 审计问题在刷新后按内容去重，保持台账稳定。

## 持久化与一致性

- 全部状态写入 `localStorage`（key：`hxwl-04-root-canal-v1`），刷新后牙位、根管、复诊与修订链保持一致。
- 修订链只追加：充填快照（v1…）永久保留，修订必须填原因；历史版本不做原地改写。
- "重置示例数据"可恢复内置三个示例牙位：#11（已充填冻结，演示 R4）、#36（双根管连续湿封，演示 R3）、#46（测长缩短缺原因 + 未测长，演示 R1/R2/R5）。
