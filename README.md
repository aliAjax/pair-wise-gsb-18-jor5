# hxwl-04 牙科根管治疗 · 复诊闭环

按**牙位 → 根管**组织工作长度、主尖锉号、封药次数与下次复诊；规则引擎拦截违规操作，
已充填病例冻结并以修订链保留全部旧版；刷新后自动做一致性校验。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS，localStorage 持久化（`rc-loop-store-v1`）。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5104。`npm run build` 可做生产构建与类型检查。

## 闭环规则

| 编号 | 规则 | 触发结果 |
| --- | --- | --- |
| R1 | 工作长度缩短超过 1mm 必须填写重新测长原因 | 未填原因保存被拦截；复测记录保留原因 |
| R2 | 未测长不得进入充填（含预约充填复诊） | 充填按钮禁用，预约/直接充填被拦截 |
| R3 | 连续封药两次仍未干燥 | 下次复诊自动改派**显微会诊**；充填与充填预约全部拦截 |
| R4 | 已充填病例冻结 | 禁止直接改/封药/重复充填；只能新建带原因修订，旧版快照保留，牙位版本 +1 |
| R5 | 刷新后一致性 | 校验牙位/根管/复诊/长度复测原因/修订链版本，异常列入冲突表 |

## 数据模型（`src/types.ts`）

- `Tooth`：牙位、诊断、版本号、根管列表。
- `Canal`：工作长度复测历史 `lengthHistory`、主尖锉号、封药次数、每次干燥情况、
  下次复诊类型与日期、充填状态。
- `Revision`：冻结更正记录，含字段、原值、新值、原因、版本前后号与**旧版根管快照**。
- `ConflictEntry`：牙位、根管、字段、原值、新值、触发规则、说明、处理类型
  （已拦截 / 已改派 / 已留痕 / 刷新校验）。

## 主要模块

- `src/engine.ts`：纯函数规则引擎（保存测长、封药、充填、冻结修订、新增牙位），
  返回新状态与冲突列表；硬性规则返回 `store=null`，状态不变但冲突留痕。
- `src/rules.ts`：规则文案、阶段推导、`integrityChecks` 刷新一致性校验。
- `src/storage.ts` / `src/seed.ts`：持久化与演示数据
  （#11 已充填带修订链、#36 封药中且 MB 需显微会诊、#46 含未测长根管）。
- `src/components/`：`ToothCard`、`CanalRow`、`ConflictPanel`、`ReviseModal`。

## 演示路径

1. `#46 / D` 根管未测长：选“下次复诊=充填”或点“进入充填”→ R2 拦截并留痕。
2. `#46 / MB` 长度从 20.0 改成 18mm 不填原因 → R1 拦截；填原因后复测历史可追溯。
3. 对已测长根管连续两次点“封药（仍未干燥）”→ 复诊自动改派显微会诊（R3），
   此后充填全部拦截。
4. `#11` 已充填冻结：点“更正（新建带原因修订）”→ 提交后 v2→v3，
   修订链可展开查看旧版快照。
5. 点“模拟刷新 / 重新校验”：从 localStorage 重载并跑 R5 校验，
   冲突表列出牙位、根管、原值、新值与触发规则。
